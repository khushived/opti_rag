🔬 How OptiRAG Works — Plain English

OptiRAG is a Retrieval-Augmented Generation (RAG) system with a twist: instead of calling the LLM for every question, it first checks if a semantically similar question was already answered. If yes — the cached answer comes back in milliseconds. If no — it retrieves relevant chunks from your documents and asks the LLM to generate a grounded answer, then caches that for next time.

Step 01
📂
Document Ingestion
You upload a PDF, image, DOCX or text file. The system extracts all text (and any images), splits it into overlapping chunks of ~512 tokens, embeds each chunk into a dense vector using Ollama, and stores everything in ChromaDB — a local vector database.
PyMuPDFpython-docxChromaDBOllama embed
Step 02
❓
Query Comes In
When you ask a question, the API accepts it and places it into an internal async queue. A background worker picks it up and starts the RAG pipeline.
FastAPIasyncio.QueuePydantic
Step 03
⚡
Semantic Cache Check
The query is embedded into a vector. All previously cached query-answer pairs are retrieved from Redis. Cosine similarity is computed between your query and each cached entry. If the best match ≥ 0.92 similarity — it's a cache hit and the answer is returned instantly, skipping all LLM calls.
Rediscosine similarityNumPy
Step 04
🗄️
Vector Retrieval (on miss)
On a cache miss, the query embedding is used to find the top-5 most relevant document chunks from ChromaDB using approximate nearest-neighbour search. These chunks become the context for the LLM.
ChromaDBHNSW indexcosine space
Step 05
🤖
LLM Generation (on miss)
The retrieved chunks are assembled into a prompt alongside your question and sent to Ollama running the mistral model locally. Mistral generates a grounded answer. If images are involved, llava (vision model) is used instead.
Ollamamistralllavahttpx
Step 06
💾
Cache & Return
The answer is stored back in Redis with its query embedding and a 24-hour TTL. Future semantically similar queries will now get a cache hit. The answer is returned to the API caller with full metadata: latency, model, sources, cache status.

🔤 What is RAG?
Retrieval-Augmented Generation is a technique where instead of asking the LLM to answer from its training data alone, you first retrieve relevant passages from your own documents and include them in the prompt. The LLM then generates an answer grounded in your actual content — reducing hallucinations and making answers verifiable.
⚡ What is Semantic Caching?
Semantic caching goes beyond exact-match caching. Instead of caching "What is the revenue?" and only matching that exact string, it caches the meaning. So "What was the total revenue?" or "How much money did we make?" all get the same cached answer — because their vector embeddings are similar enough (cosine similarity ≥ 0.92).
🧠 What is an Embedding?
An embedding is a list of ~768 numbers that represent the meaning of a piece of text. The nomic-embed-text model (via Ollama) converts any text into this vector. Texts with similar meaning have vectors that are close together — enabling similarity search and semantic caching. It's like coordinates in meaning-space.
📐 What is Cosine Similarity?
Cosine similarity measures the angle between two vectors. A score of 1.0 means identical meaning, 0.0 means unrelated. OptiRAG uses a threshold of 0.92 — meaning two questions must be 92% semantically similar to count as a cache hit. This is tight enough to avoid wrong answers but flexible enough to catch paraphrases.
